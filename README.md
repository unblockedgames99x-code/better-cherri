# Better Cherri 2.2

Better Cherri keeps Cherri’s original chat interface and uses the free yax.im XMPP service for separate private rooms and saved message history. Games, music, Show all, and repeat-one use the existing Cherri client/services. No server runs on your PC and no hosting subscription was purchased.

For direct hosted access, open https://unblockedgames99x-code.github.io/better-cherri/app.html . It loads the app immediately from the same pinned jsDelivr release, with no additional launch button; the hosted URL remains visible. This is also the fallback for browsers that cannot manage blank popups.

For the blank-tab launcher, open index.html or Better-Cherri-Launcher.html and click Launch Better Cherri once. The button requests a new about:blank tab and loads app.js from its embedded jsDelivr URL. There are no bookmark installation or file-picker steps. Popup restrictions may prevent the new tab from opening. The hosted button launcher is at https://unblockedgames99x-code.github.io/better-cherri/ and the source is at https://github.com/unblockedgames99x-code/better-cherri. The HTML’s embedded CDN link identifies the exact app release; release launchers pin app.js to its Git commit.

Open Chatrooms, choose Create account (no email), and enter your username, password, and password confirmation directly inside Better Cherri. Read and accept yax.im’s terms and privacy policy, then click Create account. No email, phone number, external signup page, registration token, or CAPTCHA step is required by this provider’s in-band registration flow. Existing yax.im accounts can sign in here too. This chat account is separate from your original Cherri account. Keep your password: yax.im does not offer email-based password recovery.

Sign-in lasts for the open app tab. The client does not save your plaintext password, so closing or reloading the app requires signing in again. Community room configuration can be saved locally or embedded in a downloaded launcher without login credentials. Closing your browser does not delete the server-side rooms or their retained history.

Chatrooms now opens the original Cherri channel layout directly. The large connection/setup banner is removed. Info contains rules, announcements, updates and links; Social contains general, general-2, art, share-music and member-shitpost; Suggestions contains suggest-games, tag-ideas, suggest-features and report-issues. These are separate Better Cherri rooms with our own messages and members. The original Cherri public rooms and member list are not connected.

The release includes one shared Better Cherri community, owned by test11124@yax.im (the account shown in the user's screenshot). When that account signs in and opens Chatrooms, missing rooms are created automatically with member-only joining, hidden room listing, persistent rooms and message archiving. The adapter checks privacy, ownership and archive settings before exposing messages. Other accounts cannot create these planned rooms through Better Cherri. If the hosted service rejects creation or a room is already owned by another account, the app reports the server error instead of claiming success.

The small Invites & settings button beside Channels opens a dialog. The owner can invite members by their full chat address, such as friend@yax.im. Download community launcher shares only public room configuration, never a password or account session. Members use their own accounts and accept invitations inside Better Cherri. Room addresses alone do not grant membership. Members and messages are scoped to the selected Better Cherri community. Info channels are writable by owners/admins through this client; the adapter does not implement Cherri's broader staff roles or moderation system.

An existing selected community or imported/downloaded community launcher takes precedence over the shared default. Earlier three-room configurations migrate in place: General becomes general, Music becomes share-music, and Games remains available. Their exact existing room addresses are retained to preserve the server's saved history. Additional regular channels are created only after the client verifies the current account owns the community. Invitations to new channels may need to be sent from Invites & settings.

The adapter preserves Cherri’s original text-chat layout and provides text messages, replies, edits to your own messages, emoji reactions, typing, scoped member lists, and archived history pagination. Message deletion is available only when the room advertises the required retraction capability; otherwise it returns an explicit unsupported-feature error. Full-text archive search, voice/video, media uploads, polls, pin management, music/playlist chat cards, Cherri friends/shop/economy, platform moderation, and original Cherri account/cloud-save services are not connected by this adapter. Unsupported actions fail explicitly; they do not fall through to Cherri’s public chat.

Messages are sent over secure WebSocket/TLS, but this release does not provide end-to-end encryption: the XMPP host can read message content. Members added later may be able to read the room history still retained by the host. yax.im’s privacy policy specifies 14-day personal message archives; chatroom history follows the respective room’s configuration and host policy. Saved messages are not a promise of permanent or unlimited retention. The volunteer service has no uptime guarantee, may remove inactive accounts after six months, and does not support high-traffic commercial use. Service rules and rate limits apply.

Official provider information: https://yaxim.org/yax.im/ ; terms: https://yaxim.org/yax.im/tos/ ; privacy and retention: https://yaxim.org/yax.im/privacy/ .

Verification: read-only checks confirmed the hosted secure WebSocket endpoint and its in-band username/password registration form without creating an account. Mocked client, bridge, and UI tests cover registration, explicit terms acceptance, authentication, private room configuration, archive handling, history pagination, member isolation, safe community exports, and cleanup. Compiled-route tests preserve the original Cherri Chat and Members components. Launcher tests check synchronous about:blank requests, deferred CDN loading, document-replacement recovery, readiness detection after the original script is removed, and failure messages. These checks do not establish that the final blank URL has been verified in every browser. No real account, private room, or chat message was created during development; registration and signed-in end-to-end delivery have not yet been verified against live accounts.

To reproduce, clone the upstream repository at the commit above into work/cherri, copy source/* into work/, and save the pristine output of git show HEAD:b/assets/bundle-i7rlf846.js from that checkout as UTF-8 work/upstream-bundle.js for tests. Run:

    node work/assemble-remote.mjs
    node work/build-remote-launcher.mjs --repo work/remote-cherri --chat-provider xmpp --out work/xmpp-full-launcher.html
    node work/build-matrix-release.mjs --full-launcher work/xmpp-full-launcher.html

The release builder retains its historical filename build-matrix-release.mjs and now packages the XMPP build. It expects a checkout of the Better Cherri repository at work/better-cherri-publish. Use --launcher-only --ref COMMIT_SHA after publishing app.js to pin the small launcher to that release. Node.js is a developer build tool and is not needed to use the launcher.
